# CROC — Pubblicare la versione 2 di Jolie su demo.lorenzoweb.it

## CONTESTO

Progetto target: ~/locali/demo-factory. Repository GitHub **pubblico**
`lorenzozenucchi/demos`, branch `main`, albero pulito all'ultima verifica.

**Cosa si pubblica.** Centro Estetico Jolie (Gazzaniga), primo cliente
firmato di Lorenzo. Alla titolare vengono proposte tre versioni complete
del sito, tra cui sceglierne una. La **versione 1** e' gia' online e
funzionante su `demo.lorenzoweb.it/centro-estetico-jolie-sito-v1/`
(verificato, risponde 200). Ora va pubblicata allo stesso modo la
**versione 2**, che deve rispondere su:

    https://demo.lorenzoweb.it/centro-estetico-jolie-sito-v2/

**Il file sorgente** e'
`~/produzione/clienti/centro-estetico-jolie/versioni/v2.html` — unico file
HTML autonomo, CSS e JS inline, 31.924 byte, riscritto il 18/09/2026.

**Le 7 fotografie** stanno in
`~/produzione/clienti/centro-estetico-jolie/foto/` e sono:
`reception.jpg`, `logo.jpg`, `cabina-trattamento-corpo.jpg`,
`trattamento-viso.jpg`, `macchinario-skinetic.jpg`, `prodotti-rhea.jpg`,
`prodotti-bbshield.jpg`. Nella stessa cartella esistono anche i `.png`
originali, molto piu' pesanti: **il sito usa i `.jpg`, e solo quelli vanno
copiati.**

**IL PUNTO CHE ROMPEREBBE IL DEPLOY, da gestire per primo.** Nel file
sorgente le immagini sono referenziate cosi':

    src="../foto/reception.jpg"

Il `../` e' corretto **dove il file sta adesso**, cioe' dentro la
sottocartella `versioni/`, con le foto un livello sopra. Nella cartella
pubblicata il file diventa `index.html` con la cartella `foto/` **accanto a
se'**, non sopra: quei path vanno quindi riscritti in `foto/...`. Se si
copia il file cosi' com'e', online il browser cerca le immagini in
`demo.lorenzoweb.it/foto/...`, che non esiste, e **tutte e sette le
fotografie risultano rotte** — con la pagina che per il resto sembra
funzionare, quindi e' un errore che passa inosservato se non lo si cerca.
La v1 non aveva questo problema perche' il suo `index.html` sta gia'
accanto alla propria cartella `foto/`.

**Come si pubblica qui.** Tutta la cartella `demos/` viene pubblicata su
Netlify in un colpo solo, sito `stalwart-sopapillas-b54243`
(id `ee1cac7a-4542-49ef-a3a6-f84c9cbc018c`), dominio custom
`demo.lorenzoweb.it`; ogni sottocartella diventa un URL. `netlify-cli` e'
gia' installato e il sito e' gia' collegato. Il `.gitignore` protegge le
foto reali dei clienti dal repo pubblico con il pattern
`demos/*-sito*/foto/`, che **copre gia' anche `-sito-v2`** — verificato con
`git check-ignore`. Non serve modificarlo.

## RUOLO

Sei l'esecutore del progetto: il task e' gia' deciso, non rimetterlo in
discussione. Non sei demo-builder ne' template-builder e non vanno
invocati: qui non si genera nessuna demo e non si crea nessun template.

## OBIETTIVO

**1. Creare la cartella** `demos/centro-estetico-jolie-sito-v2/` con dentro
una sottocartella `foto/`.

**2. Copiare il sito rinominandolo.** `versioni/v2.html` diventa
`demos/centro-estetico-jolie-sito-v2/**index.html**`. Il nome `index.html`
non e' un dettaglio: e' quello che fa rispondere l'URL come
`/centro-estetico-jolie-sito-v2/` invece di costringere a scrivere il nome
del file nell'indirizzo.

**3. Correggere i path delle immagini nella copia** (vedi Contesto):
`../foto/` diventa `foto/`. **Solo nella copia dentro `demos/`**: il file
sorgente in ~/produzione resta con i suoi `../foto/`, che li' sono giusti.

**4. Copiare le 7 fotografie `.jpg`** in
`demos/centro-estetico-jolie-sito-v2/foto/`. Solo i `.jpg`, nessun `.png`.

**5. Verificare la cartella prima di pubblicare.** Tutti controlli da riga
di comando, con l'esito nel resoconto:
   - nella copia, `grep -c '\.\./foto/'` restituisce **0**
   - nella copia, `grep -c 'src="foto/'` restituisce **7**
   - ognuno dei sette file referenziati **esiste davvero** in
     `demos/centro-estetico-jolie-sito-v2/foto/`: verificalo estraendo i
     nomi dall'HTML e controllandoli uno per uno, non fidandoti dell'elenco
     che ti ho dato nel Contesto
   - il file non contiene nulla di rotto rimasto dal lavoro precedente:
     `grep -icE 'scrim|hero-reveal|--avorio-tenue|6c4f96|54397a|--viola|25D366|utm_source|stkn='`
     restituisce 0
   - `grep -c '393314660537'` restituisce esattamente 2 (e' il numero di
     Lorenzo, nella fascia CTA e nel footer) e `grep -c 'wa.me/39035738178'`
     almeno 1 (il WhatsApp del centro)

**6. Controllo di sicurezza sul repo pubblico, obbligatorio.** Esegui
`git status --short` e `git add --dry-run -A` e verifica che **nessuna**
di queste cose compaia tra i file che verrebbero inviati:
   - qualsiasi path sotto `riferimenti/` o `riferimenti-template/`
   - **qualsiasi immagine sotto un `demos/*-sito*/foto/`**, di qualunque
     cliente — comprese le sette appena copiate
Riporta l'elenco completo dei file che verrebbero committati. Se compare
anche una sola immagine di cliente, **fermati e segnalalo**: vorrebbe dire
che il pattern del `.gitignore` non sta coprendo questo caso.

**7. Preparare a Lorenzo i comandi, senza lanciarli.** Per convenzione di
questo progetto (CLAUDE.md, "Come si lavora qui", punto 4) git commit e
push li fa Lorenzo a mano, e la pubblicazione e' un'azione verso l'esterno.
Lasciagli un blocco copia-incolla, in ordine, gia' compilato con i valori
reali:
   - `git add -A` e il commit, con un messaggio che dica cosa si e'
     aggiunto (la versione 2 del sito Jolie tra le demo, come -sito-v2)
   - il push su `main`
   - il deploy, che e' esattamente questo e **con il `--dir=demos` non
     negoziabile** (vedi Vincoli):

     npx netlify deploy --prod --dir=demos --site=ee1cac7a-4542-49ef-a3a6-f84c9cbc018c

   - subito dopo, le verifiche del punto 8

**8. Scrivere le verifiche post-deploy come richieste vere sull'URL
pubblico**, non come impostazioni lette. Nel blocco di comandi includi dei
`curl` che dimostrino:
   - `https://demo.lorenzoweb.it/centro-estetico-jolie-sito-v2/` risponde
     **200** e il corpo contiene **`glare-hover`** — quella stringa compare
     3 volte nella v2 e **zero volte nella v1**, quindi e' la prova che
     l'URL sta servendo la versione giusta e non una copia della v1 o una
     pagina in cache. Un 200 da solo non proverebbe niente.
   - **tutte e sette le fotografie rispondono 200**, non una a campione:
     sono l'unica parte del sito che il push su GitHub non dimostra in
     alcun modo, perche' il `.gitignore` le tiene fuori dal repo di
     proposito. Ed e' esattamente il punto dove l'errore dei path
     `../foto/` si manifesterebbe. Scrivi un ciclo che le provi tutte e
     stampi nome e codice di stato.
   - la **v1 risponde ancora 200** e continua a contenere il suo
     `kinetic-headline`: il deploy ripubblica l'intera cartella `demos/`, e
     va verificato che non abbia disturbato quello che era gia' online.

**Criterio di fatto / non fatto:**
- esiste `demos/centro-estetico-jolie-sito-v2/index.html` con zero
  occorrenze di `../foto/` e sette `src="foto/`
- esistono le 7 `.jpg` in `demos/centro-estetico-jolie-sito-v2/foto/`
- `git check-ignore -v demos/centro-estetico-jolie-sito-v2/foto/logo.jpg`
  stampa una riga di match
- l'elenco dei file da committare non contiene nessuna immagine di cliente
- Lorenzo ha in mano un blocco di comandi completo, da `git add` fino alle
  verifiche curl, con il ciclo su tutte e sette le foto

## VINCOLI

- **`--dir=demos` nel comando di deploy non e' opzionale.** Il file
  `.netlify/netlify.toml` di questa cartella contiene
  `publish = "/home/lorenzo/locali/demo-factory"`, cioe' la cartella
  intera: un `netlify deploy --prod` senza `--dir=demos` pubblicherebbe
  online tutto demo-factory, compresa `riferimenti/` (foto e dati di
  attivita' che non sono clienti: privacy) e `riferimenti-template/`
  (screenshot di siti di terzi: copyright). Il `.gitignore` non protegge da
  questo: vale per Git, non per Netlify. Non proporre mai a Lorenzo una
  variante del comando senza quel flag, e non modificare `netlify.toml` per
  "sistemare" la cosa.
- **Non modificare il file sorgente in ~/produzione**, in nessun modo: la
  riscrittura dei path avviene solo sulla copia dentro `demos/`. Da
  ~/produzione si legge e si copia, punto.
- **Non toccare `demos/centro-estetico-jolie-sito-v1/`**: la versione 1 e'
  online e approvata, resta esattamente com'e'.
- **Non toccare `demos/centro-estetico-jolie/`**: e' un'altra cosa ancora,
  la vecchia demo di vendita di agosto, generata da template quando Jolie
  era solo un prospect. Non rinominarla, non aggiornarla, non cancellarla.
- **Non modificare il `.gitignore`**: il pattern copre gia' questo caso, ed
  e' stato verificato.
- **Non ottimizzare, ricomprimere o ridimensionare le fotografie**: si
  copiano identiche.
- **Non toccare** `templates/`, `templates-candidati/`, `riferimenti/`,
  `riferimenti-template/`, ne' le altre demo in `demos/`.
- **Non eseguire tu git commit, git push ne' il deploy** (vedi Obiettivo,
  punto 7): prepari e verifichi, lancia Lorenzo.
- Il deploy ripubblica per forza l'intera cartella `demos/` con tutte le
  demo degli altri prospect: e' il funzionamento normale qui, non un
  effetto collaterale da evitare.
- **Se in dubbio bloccante, fermati e chiedi a Lorenzo.** In particolare se
  il controllo del punto 6 mostra file inattesi tra quelli da committare:
  non risolverlo aggiungendo righe al `.gitignore` di tua iniziativa.
